How to use the collection

  1. Set the baseUrl collection variable (defaults to http://localhost:3000).
  2. Run Auth → Login first. The session is an httpOnly cookie, so Postman stores it in its cookie jar automatically — there is no token to copy.
  3. Requests in Author and Admin need a session with the matching role:
    • admin — admin@bookleaf.test / bookleaf123
    • author — priya.sharma@email.com / bookleaf123

Create Ticket writes the new ticketId into the ticketId collection variable, so every ticket-scoped request works straight after it.

Session & errors

Authentication is a signed JWT in an httpOnly cookie named bookleaf_session — never a bearer token, so identity is taken from the cookie and never from the request body. Failures use a single envelope: { error: { code, message } }.

Queue (urgency sort)

{{baseUrl}}/api/admin/tickets?sort=urgency&page=1&limit=20

The support queue. Filtering, sorting and pagination are all done in a single MongoDB aggregation.

sort=urgency ranks status first (unresolved above resolved), then priority (Critical → Low), then oldest first.

Query parameters

NameExampleNotes
sorturgency
page1
limit20
status (disabled)Open
category (disabled)Royalty & Payments
priority (disabled)Critical
assignedTo (disabled)me
from (disabled)2026-10-01
to (disabled)2026-10-29
q (disabled)royalty
Assertions
pm.test('200 OK', function () { pm.response.to.have.status(200); });
pm.test('urgency order puts unresolved, high-priority, older work first', function () {
  const items = pm.response.json().data.items;
  const rank = { 'Open': 0, 'In Progress': 0, 'Resolved': 1, 'Closed': 1 };
  const prank = { Critical: 0, High: 1, Medium: 2, Low: 3 };
  for (let i = 1; i < items.length; i++) {
    const a = items[i - 1], b = items[i];
    const ka = [rank[a.status], prank[a.priority]].join('-');
    const kb = [rank[b.status], prank[b.priority]].join('-');
    pm.expect(ka <= kb).to.be.true;
  }
});
